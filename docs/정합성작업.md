# 데이터 정합성 검증 작업 (2026-09-03~)

`docs/크롤러현황.md`는 수집 현황용 문서라 성격이 다름 — 이 문서는 이미 DB에
적재된 데이터의 정확도/정합성을 검증·정정하는 작업만 기록한다. 갤러리 신규
확장 작업은 이 시점부터 중단하고 이 작업으로 전환했다.

## 1. gallery_representations 작가 매칭 감사

### 배경
`pipeline/store.py`의 `get_or_create_artist()`는 `name.lower()` 완전일치로만
기존 작가를 찾는다. 갤러리 크롤러가 가져온 표기(중간이름 생략, "성, 이름" vs
"이름 성" 순서, 악센트 유무, 대소문자 등)가 미술관 소장품 표기와 다르면 실제
동일 인물인데 별개 `artists` 행으로 중복 생성됐을 수 있다는 게 감사 가설.

### 방법 — `pipeline/audit_gallery_artist_matches.py` (리포트 전용, DB 변경 없음)
이름을 정규화(유니코드 NFKD 분해 후 결합문자 제거로 악센트 제거, 구두점/여분
공백 제거, 소문자화)해서 그룹화 — 정규화 결과는 같은데 `artists.id`가 다른
그룹을 찾고, 그중 `gallery_representations`로 연결된 작가가 하나라도 포함된
그룹만 우선 출력한다.

### 결과 (2026-09-03 시점)
- `artists` 전체 195,503건 (다른 세션의 크롤링이 동시 진행 중이라 계속 늘어남)
- `gallery_representations`로 연결된 고유 `artist_id` 3,786건
- 정규화 후 이름이 같은데 id가 다른 그룹: 전체 1,251개, 그중 갤러리 작가가
  하나라도 포함된 그룹 64개

### 근본 원인 4가지 (샘플로 확인)
1. **"성, 이름" ↔ "이름 성" 표기 순서** — 미술관 소스는 `"Kusama, Yayoi"`처럼
   라이브러리 목록 관행(성 먼저 쉼표)을 쓰는 경우가 많고, 갤러리 사이트는
   `"Kusama Yayoi"`/`"LEE Ufan"`처럼 자연스러운 순서를 씀. 예: Zao Wou-Ki,
   Chen Zhen, Ai Weiwei, Lee Ufan, Morimura Yasumasa, Park Young-sook 등.
2. **악센트/발음부호 유무** — Cézanne/Cezanne, Brâncuși/Brancusi,
   Nicolas de Staël/Stael, Félix González-Torres/Felix Gonzalez-Torres,
   Ólafur Elíasson/Olafur Eliasson, Léonor Fini/Leonor Fini,
   María Berrío/Maria Berrio, Eugène/Eugene Delacroix, Günther/Gunther Förg 등.
3. **유니코드 정규화 형태(NFC/NFD) 불일치** — 화면엔 완전히 동일해 보이지만
   내부 인코딩이 조합형(NFC, 완성된 é 한 글자)과 분해형(NFD, e + 결합 악센트
   두 글자)으로 섞여 있어 SQL `lower()`로도 다른 문자열로 남는 경우.
   `merge_case_dup_artists.py`(순수 대소문자 차이만 잡음)로는 못 잡는 케이스라
   `pipeline/merge_unicode_form_dup_artists.py`를 새로 작성해 별도 처리(아래).
4. **하이픈/공백 변형** — `"Lee Kunyong"` vs `"Lee Kun-Yong"`, 이중 공백
   (`"Rachel Harrison"` vs `"Rachel  Harrison"`) 등 사소한 타이포성 차이.

### 조치
- **`pipeline/merge_unicode_form_dup_artists.py` 신규 작성 후 실행** — 순수
  유니코드 정규화 형태 차이(원인 3번)만 좁게 잡아 병합. 이건 사람이 봐도
  100% 동일 표기라 동명이인 위험이 전혀 없는 케이스라서 자동 병합해도 안전
  하다고 판단(`merge_case_dup_artists.py`와 동일한 canonical 선택 로직:
  전체 대문자 아닌 쪽 우선 → 메타데이터 채워진 쪽 우선). **9개 그룹 발견,
  4건 병합**(대부분 협업자 다중 표기 문자열이었고, 리포트에서 본 ANDRÉ
  BUTZER/André Butzer류는 이 그룹에 없었음 — 즉 그 케이스들은 NFC/NFD
  차이가 아니라 원인 1·2·4에 해당해서 이 스크립트로는 안 잡힘).
- `merge_case_dup_artists.py`(기존, 순수 대소문자 차이)도 재실행 확인 —
  현재 대상 0건(이미 case-insensitive 캐시 적용 이후라 신규 중복 없음).
- **원인 1·2·4(표기 순서/악센트/하이픈 차이)는 자동 병합하지 않음** —
  다른 세션의 `merge_cross_lang_artists.py` 사례처럼 "크로스랭귀지 목록이
  완전하지 않다"는 전례가 있듯, 이런 표기 차이 병합은 동명이인(다른 사람인데
  우연히 같은 철자)을 잘못 합칠 위험이 있어 사람이 케이스별로 검토해야 함.
  이번 감사에서 찾은 64개 그룹 자체는 재현 가능(`audit_gallery_artist_matches.py`
  재실행)하니, 후속 작업에서 화가별로 실존 인물 확인 후 수동/반자동 병합
  진행할 것을 권장.

### 조치 (추가) — `pipeline/merge_name_order_dup_artists.py` 신규 작성 후 실행
원인 1번(성/이름 표기 순서 차이)만 좁게 잡아 자동 병합하는 스크립트를
작성했다. 안전 조건 3가지를 전부 만족해야 병합 대상:
1. 이름을 정규화(악센트 제거, 구두점 제거, 소문자화)해서 토큰으로 쪼갰을 때
   토큰 멀티셋이 완전히 동일(순서만 다르고 토큰 추가/누락 없음).
2. 그룹 안에 쉼표 형태("성, 이름")와 쉼표 없는 형태가 최소 하나씩 공존 —
   즉 실제로 "표기 순서가 바뀌었다"는 증거가 있어야 함(우연한 토큰 애너그램
   방지).
3. 토큰 수 2개 이상.

canonical 선택: 메타데이터(국적/생몰년) 채워진 쪽 우선 → 쉼표 없는 자연스러운
순서 표기 우선 → 전체 대문자 아닌 쪽.

**리포트 결과 12,089개 그룹**(애초 감사에서 본 갤러리 연결 64개보다 훨씬
큰 DB 전체 스코프 — NGA 등 도서관 목록식 "성, 이름" 표기가 전체 DB에
광범위하게 퍼져 있었음). 샘플 확인 결과 오탐 없음(Rembrandt Peale, Sir
Joshua Reynolds 변형들, Renoir/Manet/Reynolds 등 전부 동일 인물의 정당한
순서 차이) — 스코프가 예상보다 훨씬 컸기 때문에 `--apply` 전에 사용자 확인
받고 진행.

**실행 중 데드락 이슈**: 최초 구현은 전체 12,089개 그룹을 한 트랜잭션에
묶고 끝에 한 번만 commit했는데, 다른 세션이 동시에 `artists`에 쓰고 있어
(크롤링/provenance_extract.py 진행 중) 트랜잭션이 너무 오래 열려있다
`psycopg2.errors.DeadlockDetected`로 47개 그룹째에서 실패 — commit 전이라
전부 롤백됨. **그룹 단위 commit + 데드락 시 최대 3회 재시도**로 수정 후
재실행.

**결과 (2026-09-03, `--apply`)**: **13,676개 artists 행 병합(삭제), 353,400건
재연결**(artworks.artist_id + gallery_representations.artist_id). 재시도/실패
로그 없이 깔끔하게 완료.

## 3. gallery_representations 완전 중복 행 (2026-09-03, 자율모드 중 발견)

메인 세션이 같은 날 auction_lots↔artworks 매칭 작업에서 "새 행이 기존
데이터와 중복되는 패턴"을 다룬다는 공유를 받고, gallery_representations에도
비슷한 문제가 있는지 점검하다 발견.

### 증상
`gallery_representations`에서 동일한 `(gallery_id, artist_id)` 쌍이 서로
다른 `source_id`로 완전히 중복 삽입된 행 7건 발견(폴라쿠퍼갤러리 3건,
OCI미술관 4건) — 이름 표기 차이로 인한 애매한 중복이 아니라 **문자 그대로
같은 갤러리+같은 작가 행이 두 번** 들어간 경우라 동명이인 위험이 없다.

### 근본 원인
갤러리 사이트 자체가 같은 작가에 대해 서로 다른 두 URL을 서빙하는 경우가
있다:
- 폴라쿠퍼갤러리: `/artists/chuck-close` 와 `/artists/chuck-close2`가
  완전히 동일한 페이지 내용을 반환(같은 사이트 안에 `/exhibitions/cecily-brown2`,
  `/exhibitions/tauba-auerbach3`처럼 숫자 접미사 중복 URL 패턴이 다수 확인됨
  — CMS가 슬러그 충돌을 숫자 접미사로 회피하면서 생긴 자체 중복으로 추정).
- OCI미술관: `artist/155`·`artist/156`처럼 다른 숫자 id 페이지가 같은
  작가 이름으로 존재(예: 박종호, 윤기언, 이미정, 조습 각각 2개 id).

`crawlers/galleries.py`의 중복 방지는 href 단위(서로 다른 href는 서로 다른
레코드로 저장)이고, `pipeline/galleries.py`의 `load()`도 `raw_path` 단위로만
이미 적재됐는지 확인했다 — 그래서 사이트 자체의 중복 URL이 두 개의 서로
다른 raw 파일로 저장되고, artist_id는 `get_or_create_artist`가 같은 이름으로
묶어주지만 `gallery_representations` insert는 매번 새로 실행돼 중복 행이
생겼다.

### 조치
- **`pipeline/dedup_gallery_representations.py` 신규 작성 후 `--apply`
  실행** — `(gallery_id, artist_id)` 완전 중복 행만 정리(먼저 들어온 것
  유지). **7건 삭제**, `gallery_representations` 4,840 → **4,833건**.
- **`pipeline/galleries.py`의 `load()`에 재발 방지 로직 추가** — 갤러리별로
  `seen_artist_ids` 집합을 유지해 같은 실행 안에서 같은 artist_id가 이미
  들어갔으면 스킵. 추가로 갤러리를 처음 만날 때 DB에 이미 있는
  `(gallery_id, artist_id)` 쌍도 미리 불러와(`store.cur` 있을 때만 —
  dry-run에는 없음) 다음 실행에서도 재발하지 않게 함.
- dry-run으로 검증: 적용 전 4,840 → 적용 후 4,833건으로 정확히 7건 줄어든
  것 확인 완료.

## 2. collectors 기관 오분류 감사/정정

### 배경

### 방법 — `pipeline/audit_collectors.py`

않음.

- **"Church"**(교회) — 화가 **Frederic Edwin Church** 등 성씨로 흔함.

- **"Temple"**(사원/성전) — 성씨로도 쓰여 애매성이 높아 제외.

- **"Parish"**(교구) — "Michael J. Parish"처럼 성씨로도 쓰임(2번째 실행에서

  X" 통째로 컬렉터명으로 잘못 뽑은 추출 버그(이 문서 범위 밖, 건드리지 않음)
  라 기관으로 분류하면 더 틀리게 되므로 제외.

### 배경

### 조사

`institute` 289건(그중 198건은 `museum` 단어와 중복), `museum` 198건,
