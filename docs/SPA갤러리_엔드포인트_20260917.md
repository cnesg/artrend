# SPA 갤러리 6곳 엔드포인트/렌더링 방식 조사 (2026-09-17)

`docs/작업분담_20260915.md` R2 당시 "SPA라 raw_html이 비어있음"으로 판정돼 보류됐던 6개 갤러리
(gladstone, lehmannmaupin, perrotin, pyo, simon, takaishii)를 재조사. 리포트만, 수집 실행 없음. 요청은
페이지당 1회·엔드포인트 호출 샘플 1건·1초 이상 간격.

## 상세

### Gladstone Gallery — Gatsby `page-data.json`
`https://www.gladstonegallery.com/page-data/exhibitions/page-data.json` (GET, 인증 불필요, 200 OK, 418KB)
```json
{"result":{"data":{"allContentfulExhibition":{"nodes":[
  {"artists":[{"name":"Ugo Rondinone"}],"endDate":"2026-10-31","startDate":"2026-09-17","title":"waterfall","slug":"ugo-rondinone-waterfall"},
  ...
]}}}}
```
230개 전시 노드 확인(placeholder 더미 1건 포함). Gatsby가 빌드 시점에 Contentful GraphQL 쿼리 결과를 정적
JSON으로 구워 넣은 것이라 **API 호출이 아니라 정적 파일 GET** — robots.txt 자체가 없어 로봇 규칙상 문제
없음. artists 필드가 이름만 있고 정규화 ID는 사이트 내부 Contentful ID(우리 DB의 artist_id와 무관).

### Lehmann Maupin — Next.js + JSON-LD
`/exhibitions` HTML 응답(200, SSR) 안에 다음 구조가 그대로 박혀 있음:
```json
{"@type":"CollectionPage","name":"현재 전시","mainEntity":{"@type":"ItemList","itemListElement":[
  {"@type":"ListItem","position":1,"name":"Untitled exhibition","url":".../exhibitions/rana-begum-2026-09-10"},
  {"@type":"ListItem","position":2,"name":"House Rules","url":".../exhibitions/anna-park-house-rules"},
  ...
]}}
```
Sanity(cdn.sanity.io) 프로젝트 ID(`a9d9nfpg`)가 페이지에 노출돼 있으나, 이미 SSR로 목록이 내려오므로 별도
Sanity API 호출 없이도 목록 확보 가능. 상세 페이지(개별 전시)가 같은 수준으로 SSR인지는 이번엔 샘플을 안
찍어봄 — 후속 확인 필요.

### Perrotin — 진짜 SPA, CMS API 미발견
`/en/agenda`(전시 페이지로 추정되는 경로, sitemap.xml 기준)의 raw HTML은 스크립트/스타일을 제거하면 가시
텍스트가 "Perrotin" 한 단어뿐 — 완전 클라이언트 렌더링. 페이지 소스에서 발견되는 `graphql.json` 엔드포인트는
`perrotin-paris.myshopify.com`(전자상거래 스토어)이지 전시 CMS가 아님 — **전시 데이터가 나오는 실제
API/CMS 엔드포인트를 찾지 못함**. 헤드리스 브라우저 렌더링 없이는 이번 스코프에서 답이 안 나옴(자산 배정
원칙상 브라우저 자동화·추가 리버스엔지니어링은 다음 단계 승인 필요).

### Pyo Gallery / Simon(사이먼리) — Wix 다이나믹 페이지
두 곳 다 Wix 기반, 사이트맵 인덱스에 전시 전용 하위 사이트맵이 별도로 있음:
- Pyo: `dynamic-exhibitions_..._sitemap.xml` — `/exhibitions/<전시슬러그>/<작가슬러그>` 형태, 최근 8년치 개별
  URL 전량 나열.
- Simon: `dynamic-exhibition_..._sitemap.xml` — `/exhibition/<연도>-<회차>` 형태.

개별 페이지를 HTTP GET하면(예: Simon `/exhibition/2026-02`) Wix가 **SSR로 `<title>`과 `<meta
name="description">`을 채워서 내려줌**:
- `<title>`: "Becoming With,Joohyun Kim, MeeNa Park, Yo-E Ryou" (전시명 + 참여작가 콤마 구분)
- `<meta description>`: "September 3 - October 15, 2026" (기간)

본문 상세(전시 소개글, 이미지)는 Wix 위젯(Wix Blocks/에디터 콘텐츠)이 클라이언트에서 렌더링해 raw HTML엔
없음 — **제목·작가·기간만 필요한 R2 스코프(exhibitions/exhibition_artists 테이블)엔 이 정도로 충분**하고,
전시 소개 텍스트까지 필요하면 JS 렌더링이 필요.

### Taka Ishii Gallery — 순수 SSR (SPA 아님)
`/en/exhibition/`(목록 첫 페이지, robots.txt 자체가 없는 사이트)의 raw HTML에 전시명·기간(`Dates: Sep 19 –
Oct 27, 2026`)·장소(`Location: ...`)·전시 설명 전문이 그대로 텍스트로 있음. **09-15 문서가 이 사이트를
"SPA라 raw_html이 비어있음" 6곳에 넣은 판정은 지금 시점엔 맞지 않음** — 워드프레스 기반 전통적 SSR 사이트로
확인됨(리뉴얼됐거나 애초에 오분류였을 가능성, 원인은 특정 못 함).

"누락 축 보강"으로 볼 여지는 있으나(R2와 동일 성격), 최종 착수는 메인 판단 필요.
