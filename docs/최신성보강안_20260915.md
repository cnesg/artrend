# 최신성 진단과 보강안 (2026-09-15)

사용자 질문: "이 프로젝트 자료 너무 옛날 거지? 최근 흐름을 보기엔 무용지물이지? 보완 방법도 같이."
답: **맞다. 현재 DB는 "과거 소장·판매 아카이브"이고, "지금 누가 어디서 활동하고 시장이 어떻게 움직이는지"를
말해줄 데이터는 구조적으로 거의 없다.** 아래는 실측 근거와, 합법 소스만으로 가능한 보강 경로다.

한 줄 요약: **1675~1944년 유럽 판매 기록 44만 + 대형 미술관 소장 204만 + Bonhams 2003~ 9만 + 갤러리 명부 5천**.
최근성 신호는 Bonhams와 갤러리 로스터 둘뿐이고, 둘 다 날짜 축이 약하다.

## 2. 왜 이렇게 됐나

- 소스 선정 기준이 "공개 API·CC0 벌크"였고, 그 기준을 통과하는 건 미술관 소장품 DB뿐이다. 현재형 데이터(경매 결과·전시·페어·뉴스)는
  대부분 유료이거나 ToS/robots로 막혀 있다(`docs/크롤러현황.md` 제외 목록 참고).
- 스키마가 "정적 사실"(작품·소장·로트) 위주라 **시간이 흐르는 사건**(전시 개최, 로스터 변동, 취득, 수상)을 넣을 자리가 없다.
- Q&A는 지금 데이터 범위를 명시하지 않아, 사용자가 "요즘 시세"를 물으면 18세기 리브르 가격이 섞여 나올 수 있다.

## 3. 보강 경로 (합법·무료 우선, 효과 큰 순)

### R1. 사건 스키마 추가 — 그릇 먼저 (0.5일, 메인)
`exhibitions(id, title, venue_kind{museum|gallery|fair|other}, venue_id, city, country, start_date, end_date, url, source_id)`,
`exhibition_artists(exhibition_id, artist_id, role)`, `artist_events(artist_id, event_kind{award|residency|acquisition|representation_start|representation_end}, event_date, detail, url, source_id)`.
`gallery_representations.start_date`는 "최초 관측일"이라도 채운다(sources.fetched_at 기준).

### R2. 이미 수집 허가를 확인한 갤러리 93곳의 전시 페이지 (2~3일, 워커)
로스터를 이미 받아온 사이트들이라 robots/ToS 재검토가 거의 필요 없다. 갤러리 사이트의 `exhibitions`(current/past)는
제목·기간·작가·장소가 구조화돼 있고, **살아 있는 작가 3,824명의 "올해 활동"을 가장 싸게 얻는 길**이다.
부수 효과: `crawlers/raw/gallery_*`의 작가 상세 `raw_html`에 이미 개인전/그룹전 이력이 들어 있는 곳이 많다 — 새 요청 없이 파싱만으로 1차 채움 가능.
로스터 크롤러를 주기(월 1회) 재실행해 `representation_start/end` 이벤트를 자동 생성하면 "갤러리 이적" 흐름도 잡힌다.

### R3. Bonhams 증분 수집을 상시화 (0.5일, 워커)
`crawlers/bonhams.py`는 sitemap 전수 + `already_fetched` 스킵 구조라 주 1회 재실행이면 최신 세일이 그대로 붙는다.
현재 유일하게 합법적인 "현재 시장" 소스이니 끊기지 않게 한다. 단, 한 경매사 표본이라 "시장 지표"로 일반화하지 않는다(문서·프롬프트에 명시).

### R4. Wikidata를 "최신성 축"으로 재활용 (M6 이후, 메인)
M6에서 작가에 QID가 붙으면 SPARQL로 다음을 작가 단위로 가져올 수 있다(CC0, API 허용):
전시 참여(P1344/P710 역참조, 전시 항목의 P580/P582 기간), 수상(P166 + P585 시점), 소속 갤러리(P?는 빈약), 사망(P570 — 생존 여부 갱신), 소장처 변화(P195).
커버리지는 유명 작가에 치우치지만 비용이 0에 가깝고 "근거 URL"이 자동으로 따라온다.

### R5. 한국 축 — 공공 API와 기관 공식 페이지 (1~2일 + 사용자 키 발급)
- **문화체육관광부 문화포털 "공연전시정보" API**(공공데이터포털, 키 발급 필요 — 사용자 결정 항목): 전국 전시 일정(기관·기간·장르). 미술관·갤러리 전시의 일정 데이터로는 국내 최대 무료 소스.
- 국립현대미술관·서울시립·리움·부산·경기 등 **이미 소장품을 수집한 기관의 전시 페이지**: robots 확인은 소장품 수집 때 이미 했으니 전시 목록만 추가.
- 예술경영지원센터 「미술시장 실태조사」·한국미술시가감정협회 연간 통계: 로트 단위가 아니라 **연간 집계(낙찰총액·낙찰률·상위 작가)** 지만 공개 PDF/Excel이라 "한국 시장 흐름" 질문엔 이걸로 답할 수 있다. 표를 `market_stats_kr(year, metric, value, source_url)`로 정형화.
- KIAF·Frieze Seoul 참가 갤러리 공식 명단(주최측 공개): `exhibitions(venue_kind='fair')` + 참가 갤러리 → 로스터 작가로 확장.

### R6. Q&A 쪽 정직성 장치 (0.5일, 메인)
- `artgraph_chat.py` 시스템 프롬프트에 데이터 범위를 고정: "경매는 1675~1944 유럽(Getty) + Bonhams 2003~현재 한 곳, 미술관 취득 시점 없음, 전시 데이터는 R2 이후".
- 답변에 "기준 시점(as of): 소스별 fetched_at 최대값"을 붙인다. 지금도 `sources.fetched_at`으로 계산 가능.
- 큐레이션 점수(`build_curated_vault.py`)에 최근 3년 사건 수를 넣어 "활동 중인 작가"와 "역사 작가"를 분리 표시.

### 무료로는 안 되는 것 (사용자 결정)
- **로트 단위 현대 경매가(Christie's/Sotheby's/Phillips/서울옥션/K옥션)** → Artprice/Artnet 유료 라이선스 외에 합법 경로 없음. 이게 없으면 "가격 흐름"은 Bonhams 한 곳 표본 + 한국 연간 집계로만 답한다.
- **전문지 비평·뉴스**(Artforum/ARTnews/Frieze 등) → ToS·robots 명시 차단. 기관 공식 보도자료·RSS만 허용.

## 4. 결정 사항 (메인 판단, 2026-09-15)
- 재진단 계획의 "새 소스 금지"는 **가비지 정리 중 분모 팽창 방지**가 목적이었다. R2·R3·R4는 이미 허가 확인된 사이트/CC0 데이터의 **누락 축 보강**이므로 P2와 병행 허용. R5의 공공 API 키 발급과 유료 라이선스는 사용자 결정 대기.
- 순서: 메인 M6(authority) → R1(스키마) → R6(프롬프트) → R4. 워커 W8·W9 → R3 → R2.
- 이 문서의 수치는 `pipeline/audit_health.py`에 "최신성" 절로 추가해 매 작업 후 재측정한다(2020년 이후 작품·로트 수, 전시 건수, 생존 작가 중 사건 보유 비율).
