# 古裂會(kogirekai) artist_id 백필 — 2026-09-23

kogirekai 낙찰품 11,778건이 **100% `artworks.artist_id` NULL** 이던 것을 조사해 2,331건(19.8%)을
authority 정확매칭으로 연결했다. 스크립트는 `pipeline/kogirekai_backfill_artist.py`
(리포트 기본 / `--apply` 반영 / 재실행 idempotent).

## 1. 원본에 작가 필드가 따로 있었나 — 없다 (로더 버그 아님)

`crawlers/raw/kogirekai/` 는 JSON이 아니라 **落札結果 PDF 17개**(+schedule HTML 11, meta 28)다.
PDF 표의 컬럼은 `番号 / 品名 / 最低価格 / 落札価格` **4열뿐**이고 작가 컬럼이 없다.
meta.json도 크롤러 메타(site_name/url/fetched_at/raw_path/license_note)뿐이라 작가 정보가 없다.
→ **로더가 필드를 놓친 게 아니다.** 기존 `pipeline/kogirekai.py` 가 artist를 안 뽑은 판단
자체는 정당했다.

다만 그 판단의 **전제**가 틀렸다. 작가명은 별도 컬럼이 아니라 `品名` 안에 들어 있고,
**넓은 공백으로 품목명과 구분**돼 있다:

```
#002 藤原定家　小倉色紙幅        → 작가 藤原定家 + 품목 小倉色紙幅
#006 伝信實　柿本人麻呂画幅      → 귀속 伝 + 작가 信實 + 품목
#001 春日鹿曼荼羅幅               → 구분자 없음 = 작가 개념 없는 골동품
#098 香木                         → 〃
```

로더 docstring이 "칸옥션의 생몰년 같은 명확한 2차 신호가 없다"고 아쉬워한 그 신호가
**이 구분자**다. "伝" 접두어를 보는 대신 구분자 앞 첫 세그먼트를 보면 `伝来`(가문 전래)
같은 오탐 문제가 애초에 생기지 않는다.

## 2. 실제로 막고 있던 것 — 조용한 인코딩 함정 3개

DB title이 아니라 **raw PDF를 다시 파싱**해야 했고, 그 과정에서 정확매칭을 조용히 0건으로
만드는 함정 3개를 실측으로 찾았다.

| # | 함정 | 실측 | 대응 |
|---|---|---|---|
| 1 | 로더가 `re.sub(r"\s+"," ")` 로 구분자를 일반 공백에 접음 | DB에는 신호가 안 남음 | raw PDF 재파싱 |
| 2 | **구분자가 회차마다 다름** — 제135~150회 `U+3000`(전각), **제132·133회 `U+2003`(EM SPACE)** | U+3000 6,719회 / U+2003 869회 | 둘 다 구분자로 처리 |
| 3 | pypdf 텍스트에 **부수 코드포인트**가 섞임 | 康熙부수(U+2F00~)는 NFKC로 풀리지만 **CJK Radicals Supplement(U+2E80~)는 표준 분해가 없어 NFKC 후에도 그대로** | 10자 수동 매핑표 |

3번 예: `⻫⽩⽯`(U+2EEB U+2F65 U+2F5F) 는 눈으로는 齊白石이지만 바이트가 달라 정확매칭이
전부 실패한다. NFKC만으로는 `⻫`(U+2EEB)가 안 풀린다.

**순서가 중요하다**: NFKC는 U+3000/U+2003도 일반 공백으로 접으므로
**구분자로 먼저 자른 뒤 세그먼트별로 NFKC** 를 걸어야 한다. 순서를 바꾸면 후보가 0건이 된다(실측).

또 `々`(U+3005)를 후보 정규식에 빠뜨리면 野々村仁清·柳々居辰斎·藪内休々斎 같은 실존 작가가
통째로 탈락한다(실측 30여 건).

### DB 대조 키
`auctions.name` 이 NULL이라 회차로 못 붙는다. 그리고 로더 `ITEM_RE` 가 로트 접두어를 버리고
숫자만 저장해서 같은 회차의 `#001` 과 `A-001` 이 **둘 다 `001`** 로 들어가 충돌한다
(11,778건 중 9,457건 충돌). **(경매일, 로트번호, NFKC(title)) 3중 키**로 11,778건이
누락·중복 0으로 1:1 대응한다.

## 3. 연결 규칙 — 유사도·LLM 없음

CLAUDE.md의 "결손 메타를 추측으로 채우지 않는다" 원칙대로 **문자열 정확일치 + authority ID**만 썼다.

1. **Wikidata ja `rdfs:label` 정확일치** + `P31=Q5`(사람) + `P106` 직업이 미술 계열.
   별칭(altLabel)은 **일부러 안 본다**(`北斎` 17건이 이 때문에 미연결 — 보수적 기본값).
   같은 라벨의 사람이 2명 이상이면 **동명이인 위험 → 보류**.
2. 얻은 QID로 `artists` 조회 → 있으면 그 행에 연결. **언어를 건너뛴 authority 연결**이 이 경로다
   (`狩野探幽` → 기존 `Kano Tan'yū` Q961405, `円山応挙` → `Maruyama Ōkyo` Q405444).
3. QID로 못 찾으면 `artists.name` NFKC 정확일치(`entity_kind='person'`, 유일할 때만).
4. 그래도 없고 Wikidata 검증을 통과했으면 `artists` 신규 생성(QID/ULAN 동반).

직업 판정은 QID 목록 대신 **영문 직업 라벨 키워드 allowlist**로 한다(동일성 판정이 아니라
범주 필터). 사람이지만 미술 직업이 아닌 경우(徳川慶喜·後醍醐天皇의 서예 등 "역사적 인물의
글씨를 작가로 볼지 애매한" 440건)는 **연결하지 않고 집계만** 한다
(`--include-nonart-humans` 로만 포함).

`伝X`(전 X 작)는 접두어를 떼고 X로 해소하되 `artworks.attribution_qualifier='伝'` 을 남긴다
(`mark_getty_attribution.py` 귀속 한정어 관례와 동일). 36건.

Wikidata SPARQL 원본은 `crawlers/raw/wikidata_kogirekai_artists/` 에 `save_raw` 로 보관(CC0).
