# Kogire-kai(古裂會) 경매 소스 착수 로그 (2026-09-22)

`docs/경매소스확장_20260922.md` B-5절 "판단 보류" 항목("robots가 가장 우호적이나 落札結果
구조·약관 미확인, 추가 조사 권장")을 실제로 조사·착수한 기록. 이 파일은 조사 담당
에이전트가 자유롭게 쓰는 로그이고, 위 원본 문서(경매소스확장_20260922.md)는 오케스트레이터가
나중에 취합해 반영한다.

## 1. 사이트 확인

- 정식 명칭: 古裂會(こぎれかい, Kogire-kai) — 교토 소재 고미술·골동 낙찰경매(칠기·다도구·
  갑주·염직물·서화·불교미술 등, 30년 운영, 카탈로그 발송 약 8,000명, 연 6회 개최)
- 도메인: **kogire-kai.co.jp**(공식 영문 페이지 `/en/`)

## 3. 이용약관 — 통과 (금지 조항 없음, 일반 ToS 페이지 자체가 없음)

사이트에 일반 이용약관(利用規約) 페이지가 없다. 대신 아래 세 페이지 전문을 확인했다:

- `/law/`(특정상거래법 표시): 회사 정보·입찰 방법·배송/반품 절차만. 크롤링/스크래핑/
  데이터마이닝/자동수집/로봇/무단복제 조항 없음.
- `/privacy/`(개인정보보호방침): "개인정보 제3자 개시하지 않음"은 있으나 이는 **이용자가
  입력한 개인정보**에 대한 조항이지 사이트 콘텐츠 재이용 제한이 아님. 크롤링 관련 조항 없음.
- `/en/bid/`(참가방법 안내): 카탈로그 구독료·입찰 방식·수수료·해외배송 제한(CITES)만.
  사진 저작권/콘텐츠 복제/정보 재배포/크롤링 관련 조항 없음.

푸터 저작권 표시는 "© 2018 kogire-kai" 한 줄뿐. **SBI Art Auction("사전 서면승낙 없이
복제·보존·가공 금지" + "제3자 정보 개시 금지"), Est-Ouest("제3자에게 결과 정보 개시 금지"),
Shinwa("저작권법이 정한 경우 외 복제 금지") 같은 다른 일본 경매사에서 반복됐던 패턴이
여기엔 전혀 없다** — 이번에 조사한 일본 경매사 중 가장 깨끗한 케이스.

다만 PDF 자체는 기본적으로 저작권 보호를 받는다고 보고(명시 조항 부재가 "재배포해도 된다"는
뜻은 아니므로), **PDF 원문은 재배포하지 않고 raw/에만 보관**, DB에는 사실 데이터(로트번호/
품명/가격)만 추출해 적재하는 방식으로 설계했다(Shinwa 케이스 대비 취지와 동일).

## 4. 落札結果 구조 — SSR + 링크가 목록 페이지에 이미 노출

- `/schedule/`(開催日程 목록)이 완전 SSR, 11페이지(2026-09-22 기준), 제102회(2018-09)~
  제152회(2027-01 예정)를 망라.
- **落札結果 PDF 링크가 상세페이지까지 안 들어가도 목록 페이지 자체에 이미 있다**:
  `<dt class="mod-yellow">落札結果</dt><dd><a href="....pdf">落札結果（PDF）</a></dd>`.
  이번 조사 시점에 실제로 링크가 걸려 있던 회차는 **17개(제132회~제150회, 2023-10~
  2026-09)** — 그 이전 회차는 이 목록 페이지에서 PDF 링크가 확인되지 않았다(결과 미게시
  또는 다른 경로로 게시된 것으로 추정, 추가 조사 안 함).
- PDF는 스캔 이미지가 아니라 **pypdf로 텍스트 추출 가능**(실물 2개로 직접 검증 후 착수).
  표 형태: `<로트id> <품명> ¥<최저가> [¥<낙찰가>|SOLD|sold]`, 유찰이면 낙찰가 칸이 비어
  있다.

## 5. 크롤러/로더 구현 — 파싱 함정 여러 개 실측으로 발견·수정

- `crawlers/kogirekai.py`: 2단계(`schedule` → 목록 11페이지 저장, `pdf` → 목록에서
  (회차, PDF URL) 추출해 PDF 원본 저장). kanauction.py 구조를 템플릿으로 사용.
- `pipeline/kogirekai.py`: PDF 텍스트를 정규식으로 파싱해 auction_lots 적재.
  **개발 중 실물 PDF 17개로 반복 검증하며 잡은 함정들**:
  1. 로트 id 접두어가 회차마다 다르다 — `#001`(일반), `CN-001`(중국미술 특집),
     `A-001`/`B-040`(공예 카테고리별), `i-001`(소문자, 인형류), 심지어 `Ｂ-085`(전각
     B, 폰트 치환 추정) 까지 확인됨. 접두어 정규식을 `(?:#|[A-Za-zＡ-Ｚａ-ｚ]{1,3}-)`로
     넓혀야 전부 잡혔다.
  2. 낙찰가 자리에 금액 대신 `SOLD`/`sold`(대소문자 둘 다 실물에서 확인)만 적힌 경우가
     있다 — 가격 비공개로 추정. 가격은 지어내지 않고 `hammer_price=None`, `sold=True`만
     남긴다(756건 해당).
  3. **가장 치명적이었던 버그**: 페이지 넘김 각주("1 / 11 ページ")나 기념호(150회
     「清華譜」)의 반복 각주("古裂會 第150回入札・記念号「清華譜」", "オークション
     落札結果一覧 N/M 날짜")를 먼저 안 지우면, 품목 경계를 찾는 lookahead가 실패해
     정규식이 역추적하며 **다음 품목 전체를 직전 품목의 title로 통째로 삼켜버렸다**
     (그 다음 품목은 통째로 유실). 수정 전 32,532건 중 365건이 이렇게 오염돼 있었다 —
     노이즈 패턴 3종을 전부 걷어낸 뒤 32,878건 전부 깨끗해진 것을 직접 확인(제목에
     `¥`/`ページ`/id패턴 잔존 0건).
  - **작가 추출은 의도적으로 하지 않았다.** 품명에 "伝OOO"(전 OOO 작) 형태로 귀속이
    붙는 경우가 있어 접두어 매칭을 시도했으나, "伝来"(대대로 전해 내려온 — 예:
    "武田家伝来色漆角高杯")처럼 귀속과 무관한 "伝"으로 시작하는 흔한 복합어가 섞여
    있어 오탐을 피할 신뢰할 만한 2차 신호가 없었다(칸옥션의 "생몰년 뒤따름" 같은
    안전장치가 여기엔 없음). 게다가 "伊藤若冲"·"沈南蘋"·"齊白石"·"鈴木百年" 같은
    실명 작가/화가가 접두어 없이 그냥 품명 맨 앞에 오는 경우도 흔해, 접두어 유무만으로
    작가 유무를 구분할 수 없었다. **오탐으로 존재하지 않는 작가를 artists 테이블에
    만드는 리스크가 크다고 판단해 이번 파일럿은 전부 artist_id=None으로 적재**했다
    (이름 유사도 병합 금지·LLM 메타 채우기 금지 원칙과 같은 방향의 보수적 선택).
    작가 귀속이 필요하면 후속 과제.
  - 가격 단위 JPY, 최저가만 있고 구간이 아니므로 `estimate_low`만 채우고
    `estimate_high`는 None.

## 7. 남은 것 / 후속 과제

- 제102회~제131회(2018-09~2023-10, 약 30개 회차)는 이번 목록 페이지에서 落札結果 PDF
  링크가 안 보였다 — 결과 미게시인지 다른 URL 패턴인지 미확인. 필요하면 후속 조사.
- 작가 귀속(伊藤若冲 등 실명 작가) 추출은 이번에 하지 않음 — 오탐 위험 때문에 보류.
  더 신뢰할 수 있는 신호(예: 품명 사전 대조, 별도 카탈로그 원문 대조)가 있으면 재검토.
- 주간 갱신잡(`refresh_weekly.ps1`) 편입은 이번 범위 밖(다른 신규 소스 2개도 마찬가지로
  보류됐다고 원본 문서에 기록돼 있음) — `crawlers/kogirekai.py`가 이미 `already_fetched`
  기반이라 증분 실행은 저렴함.
