# Phillips(www.phillips.com) 착수 조사 — 2026-09-22

`docs/경매소스확장_20260922.md` A-3절이 "조건부 가능(미착수)"로 남겨 둔 것을 더 깊게 파서
실제 착수한 기록. 결론부터: **조건부 진행 — 소규모 파일럿(8세일 792건) 성공, 단 전면 확장은
사이트의 활성 봇 차단(간헐적 403) 때문에 이번 세션에서는 보류**. 우회 시도는 하지 않았다
(아래 "봇 차단 발견과 판단" 참고).

## 1. robots.txt 재확인 (지시 1번)

2026-09-22 재확인 결과 문서 기록과 동일:
```
Disallow: /bin/
Disallow: /message/optin/
Disallow: /Search
Disallow: /search
Disallow: /SEARCH
Disallow: /phillips/otis
Disallow: /*/filter/
```
`/auctions/past`, `/auction/<saleNumber>` 모두 disallow 목록에 없음. `/*/filter/`만 피하면
된다(과거경매 탐색 UI의 필터 링크가 `/auctions/past/filter/Year%3D2024/...` 형태 — 이 경로는
아예 쓰지 않았다. 대신 임베드 JSON에서 세일 목록을 직접 뽑는 방식을 썼다, 아래 4번 참고).

## 2. 이용약관을 더 적극적으로 찾기 (지시 2번) — 여전히 못 찾음, 이번엔 더 강한 부존재 정황

- **사이트 자체의 Site Map 페이지**(`/sitemap`)를 직접 열어 전체 사이트 구조를 확인했다.
  Footer 카테고리가 "Location / Privacy Policy / Careers / Press / Cookie Policy /
  Modern Slavery Policy"뿐이고 "Policies" 상위 카테고리 안에도 이 셋만 있다. **Terms /
  Legal 카테고리 자체가 사이트 내비게이션 구조에 없다** — 08-17/09-22 조사가 "못 찾았다"에
  머물렀던 것과 달리, 이번엔 사이트가 스스로 공개한 완전한 사이트맵으로 "찾을 자리 자체가
  없다"까지 확인했다. 부존재 증명은 여전히 아니지만 정황이 한 단계 강해졌다.
- Privacy Policy(`/about/privacy`) 본문 확인: "It should be read in conjunction with other
  terms and conditions that you are asked to sign if and when you use our services" 라는
  문구만 있고(구체적으로 경매 참여 시 서명하는 Conditions of Sale을 가리키는 것으로 보임),
  크롤링/스크래핑/로봇/데이터마이닝 관련 문구는 전무.
- Google 검색(`site:phillips.com terms of use`, `site:phillips.com "terms and conditions"`):
  Conditions of Sale PDF(경매 참여자용, `dist.phillips.com/.../Phillips_Online_COS_NY...pdf`)만
  나오고 웹사이트 이용 자체에 대한 일반 ToU는 여전히 안 나옴.
- Wayback Machine CDX API로 `phillips.com/terms*`, `www.phillips.com/terms*` 과거 스냅샷을
  조회 시도 — **Internet Archive 자체가 조사 시점에 일시 장애**(`504 Gateway Time-out` /
  "Internet Archive: Temporarily Offline")라 결론에 반영하지 못했다. 이 경로는 미완으로
  남는다(다음에 재시도 가능).
- **결론(지시 3번 기준)**: robots.txt 명시 허용 + Privacy Policy에 금지 문구 없음 + ToU
  자체가 게시돼 있지 않음(사이트맵으로 재확인, 09-17/09-22보다 근거 강화) — 조합 요건을
  충족해 **가벼운 point-in-time 수집을 조건부로 진행**했다.

## 3. 결과 페이지 구조 확인 (지시 4번)

- `/auctions/past` 자체가 **완전 SSR**이고(놀랍게도 `curl`만으로 7.2MB 전체 HTML을 그대로
  받음), 게다가 `ReactDOM.hydrate(React.createElement(PhillipsReact.PastAuctions,
  {"data":[...]}), ...)` 형태로 **과거 세일 897건 전체의 메타(saleNumber/제목/지역/날짜/
  부서)가 JSON으로 그대로 박혀 있다**. `?year=` 쿼리 파라미터를 줘도 서버가 같은 전체
  목록을 반환한다(필터링은 클라이언트 JS 몫) — 그래서 목록 수집은 **1회 요청으로 충분**하다.
- 세일 상세 페이지(`/auction/<saleNumber>`)도 완전 SSR. 로트 그리드
  (`data-testid="lot-<id>-object-tile"` 블록 반복)에 로트번호·작가·작품명·추정가·
  낙찰가(유찰이면 "Sold For" 블록 자체가 없음)가 plain HTML 텍스트로 있다. `curl` 원문
  확인: UK030426(David Hockney 세일) 1장에 "Sold For" 75회, "David Hockney" 121회 등장.
- 통화는 지역별로 다르다 — 확인된 것만 `£`(런던), `CHF`(제네바, 기호 없이 "CHF139,700"
  형태), `$`(뉴욕, USD로 처리). 홍콩(`HK$`)·파리(`€`)·싱가포르(`S$`)는 이번 파일럿
  8세일에는 안 걸려서 실측은 못 했지만 파서에 이미 대응 규칙을 넣어 뒀다.

## 5. 봇 차단 발견과 판단 — 왜 파일럿을 8세일에서 멈췄는가

`crawlers/phillips.py --phase auctions --limit 25`를 요청 간 1.5초 딜레이로 돌렸는데,
**처음 8세일은 전부 200으로 성공했지만 9번째부터 전부 403 Forbidden**으로 막혔다(4회
재시도까지 전부 실패). 백그라운드 작업을 즉시 중단했다.

그 직후 진단(재시도가 아니라 "지금 상태가 뭔지 확인"용으로 최소한만 수행):
- 같은 URL을 `curl`로 재요청 → 200 (성공).
- 같은 URL을 Python `requests`로 재요청(몇 분 뒤) → 200 (아까는 403이던 게 성공).
- 그 직후 `/auctions/past`(아까 잘 됐던 경로)를 다시 요청 → 403.
- 20분 이상 지난 뒤 6초 간격으로 2건 재확인 → 1건 200, 1건 403.

패턴이 "버스트 이후 일정 시간 차단됐다가 풀린다"(단순 레이트리밋)이 아니라 **시간이 꽤
지나도 대략 절반 정도가 무작위로 403** — 특정 클라이언트·특정 경로만 막히는 것도 아니고
(curl도 나중엔 같이 막혔을 가능성이 있음, 재확인은 안 함), 지연을 늘려도 해소되지 않는
패턴이다. Akamai류 엣지 봇 탐지가 확률적으로 챌린지를 거는 것으로 보인다 — 이 프로젝트가
이미 Dorotheum에 적용한 기준(robots.txt는 허용해도 **실제로 Cloudflare managed challenge가
상시 작동**하면 "robots 차단"이 아니라 "봇 챌린지"로 분류하고 제외)과 같은 상황이다.

**우회 시도는 하지 않았다**: User-Agent 변경, 헤더 위장, TLS/클라이언트 지문 조작, 지연시간을
탐지 회피 목적으로 조정하는 것 등 어떤 형태의 봇 탐지 우회도 시도하지 않고 여기서 멈췄다.
이미 성공적으로 받은 8세일(위 curl 재확인 성공분 포함, 정상적으로 얻은 데이터)만 적재했다.

## 8. 후속 과제 (이번엔 일부러 안 한 것)

1. **나머지 540개 미술 전용 세일 확장** — 봇 차단이 간헐적이라 며칠에 걸쳐 소량씩(예:
   하루 10~20세일) 나눠 돌리거나, 시간을 바꿔 가며 재시도하는 방식을 권한다. 크롤러가
   이미 `already_fetched` 기반이라 언제 다시 돌려도 이어받기는 안전하다. **어떤 형태든
   봇 탐지를 우회하는 방향(헤더/TLS 위장, 프록시 로테이션 등)으로는 절대 접근하지 말 것** —
   차단이 계속되면 Dorotheum과 같은 기준으로 이 소스를 완전히 접는 것도 정당한 선택지다.
2. **Wayback Machine ToU 스냅샷 재조회** — Internet Archive 장애로 이번엔 확인 못 함.
3. **HK$/€/S$ 통화 실측** — 이번 파일럿 8세일에 홍콩·파리·싱가포르 세일이 없어 파서의
   해당 통화 처리는 코드 리뷰로만 검증됐고 실제 데이터로는 아직 못 봤다. 확장 시 첫
   홍콩/파리 세일에서 표본 확인 필요.
