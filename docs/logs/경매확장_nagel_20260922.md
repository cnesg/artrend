# Nagel Auktionen(auction.de) 경매 소스 확장 — 조사 + 파일럿 (2026-09-22)

지시 배경: Grisebach(독일) 성공 이후, 같은 독일어권 경매사 확장 축으로 Nagel Auktionen(슈투트가르트)을
조사·착수. 판정 기준은 `docs/경매소스확장_20260922.md`(B-2 Grisebach 통과 근거, B-4 불가 확정 사례들)를
대조 기준으로 삼았다.

## 0. 지시받은 도메인이 틀렸다

지시받은 `nagel-auktionen.com`은 **DNS NXDOMAIN — 존재하지 않는 도메인**이다(`nslookup`,
`curl` 둘 다 2026-09-22 직접 확인, "Non-existent domain"). 웹 검색으로 재확인한 결과 Nagel
Auktionen의 실제 공식 도메인은 **`www.auction.de`**다(Wikipedia·명함 연락처·소셜 계정이 모두
이 도메인을 가리킴). 이하 전부 `www.auction.de` 기준으로 조사했다.

## 1. robots.txt — 통과

```
User-agent: *
Disallow: /wp-content/uploads/wpforms/
Sitemap: https://www.auction.de/wp-sitemap.xml
Sitemap: https://www.auction.de/sitemap.xml
```

전면 허용(빈 `Disallow`)에 워드프레스 폼 업로드 경로 하나만 예외. Grisebach처럼
`anthropic-ai`/`ClaudeBot`을 이름으로 지목한 명시적 허용은 없지만, Lempertz·K-ARTMARKET과
같은 패턴으로 AI 봇을 이름으로 차단하지도 않는다. 이 크롤러가 쓰는 `/en/auction-*/`,
`/en/auctions/lot/`, `/en/service/result-lists/` 전부 허용 범위.

## 2. ToS 원문 확인 — 크롤링 특정 금지 조항 없음

- **Conditions of Sale**(영문 `/en/conditions-of-sale/`, 독문 `/versteigerungsbedingungen/`
  둘 다 전문 확인): crawl/scrape/spider/robot/data mining/harvest/automat/systematic/
  §44b UrhG(TDM 유보) 키워드 전부 **미검출**. §26 UrhG(추급권/저작권료)만 언급되는데
  이건 재판매 로열티 조항이라 무관.
- **Legal Notice**(`/en/legal-notice/`)에 범용 저작권 고지 있음: "The content of these
  websites may not be copied, distributed, modified or made accessible to third parties
  **for commercial purposes**." → 크롤링/스크래핑을 특정해 금지하는 문구가 아니라 상업적
  재배포를 금지하는 통상적 저작권 고지 — Grisebach·Lempertz·K-ARTMARKET에도 동급 고지가
  있고, 이 프로젝트가 지금까지 적용한 기준("크롤링 특정 금지 키워드 존재 여부")으로는 통과.
  이미지는 수집하지 않고(사실 데이터만) 비상업적 연구 목적이라 이 조항과 충돌하지 않는다고
  판단.
- reCAPTCHA/hCaptcha/Turnstile 스크립트가 페이지에 로드되지만 **문의·위탁 폼 제출에만
  걸리는 것**이고, 일반 페이지 열람(카탈로그·로트 상세·결과 목록)은 캡차 없이 평문 GET으로
  200을 받는다(직접 확인) — the-saleroom.com류의 능동적 봇 차단과는 다르다.

**결론: robots.txt 통과 + ToS 통과 둘 다 충족 — 가능.**

## 3. 구조 — Grisebach보다 로트 단위 데이터가 더 풍부함

세 종류 페이지를 조합한다:

1. **`/en/service/result-lists/`** — 경매 코드·부문명·날짜(연도 헤더+표, 2020~2026, 52개
   회차) 한 페이지. 결과 PDF(`/Result/<code>.pdf`) 링크도 있지만 **PDF에는 로트번호+낙찰가만
   있고 작가명이 없어서**(예: "2001 € 2.600,-") 이 프로젝트 스키마(artist 귀속 필수)에
   단독으로는 못 쓴다 — 날짜/코드 판정용으로만 쓰고 PDF 자체는 받지 않는다.
2. **`/en/auction-<code>/?items_per_page=500`** — 코드별 카탈로그 목록(완전 SSR). 로트당
   썸네일+로트번호+작가명(또는 무명품이면 작품 제목)+추정가, 그리고 **로트 상세 페이지로
   가는 정확한 링크**(`auction_uid`+`lot_id`+`suffix` 쿼리) 500건/요청으로 한 번에 받힌다.
   **카탈로그 페이지는 최근 회차만 남아 있다** — 2026-09-22 확인 결과 대략 코드 811(2023년)
   이후는 200, 그 이전(2020~2022, 코드 785~810)은 404. 사이트 쪽 보존 기간으로 추정.
   가장 최근 코드 847도 404였다(사후 정리 지연 추정) — 52개 코드 중 카탈로그가 남은 건
   약 36개.
3. **`/en/auctions/lot/?auction_uid=X&lot_id=Y&suffix=Z`** — 로트 상세 페이지 한 장에
   **작가명(또는 무명품 제목)·생몰년(있으면)·치수·설명(재질/연도/전시이력/출처)·추정가·
   낙찰가**가 전부 완전 SSR로 들어 있다. 특히 낙찰가가
   `<section class="…zuschlagspreis" data-value="3.108 €">`처럼 **속성값으로 깔끔하게
   분리**돼 있어 파싱이 Grisebach보다 오히려 쉽다(유찰이면 `data-value=""`).

작가 판정 함정(칸옥션과 동일 패턴): Description 첫 줄이 "도시, YYYY - 도시, YYYY" 생몰년
패턴이면 작가로, "Ancient Gandhara region, 2nd/3rd cent. AD"처럼 산지·시대 표기면 무명
공예품(artist_id=None, 제목만 저장)으로 처리한다.

낙찰가는 **구매수수료+부가세 포함가**("incl. Premium and VAT") — Grisebach(구매수수료 포함,
부가세 별도)·Bonhams(해머 프라이스)와 각각 정의가 달라, 소스 간 비교는 원래부터 source를
봐야 하는 구조.

## 4. 만든 것

| 파일 | 내용 |
|---|---|
| `crawlers/nagel.py` | `--phase codes`(결과목록 페이지) / `list`(코드별 카탈로그, 500건/요청) / `lots`(로트 상세) / `all`. `--max-auctions`, `--max-lots-per-auction`로 파일럿 범위 제한 가능. Crawl-delay 1.75초(robots.txt에 명시 없어 지시받은 1.5~2초 범위 적용) |
| `pipeline/nagel.py` | 위 HTML 파싱 → auction_houses/auctions/auction_lots. 작가 생몰년 패턴 판정, 독일식 숫자(`1.000,50 €`) 파싱, 영/독 혼용 날짜 파싱(`_parse_auction_date`) 포함 |
| `pipeline/_scratch/load_nagel_20260922.py` | run.py를 거치지 않는 1회성 적재 스크립트(PgStore 직접 호출) |

## 5. 파일럿 실행 결과

카탈로그가 남아있는 최신 6개 회차(846·845·842·839·838·837)에서 회차당 최대 10로트씩
샘플로 수집 — 전체 백필이 아니라 **크롤러/로더 동작 검증용 파일럿**이다.

- 수집: 52로트 상세 페이지 저장(회차 837은 표본 10건이 전부 유찰이라 적재 0건)
- 적재: **43건**(유찰/결과없음 17건 스킵) — 경매 5회차(2025-12-08, 2026-02-04, 2026-03-11,
  2026-05-13, 2026-07-13)
- 작가 귀속: named-artist 10건(작가 6명 — Corinth Lovis/Hölzel Adolf/Hofmann Ludwig von/
  Schlobach Willy/Haueisen Albert/Hartogh Rudolf Franz, 전부 생몰년 정확히 파싱됨), 무명
  공예품(Asian Art·Silver 등) 33건(artist_id NULL, 제목만 저장 — 의도된 동작)
- SELECT 표본 확인(코드 839, Modern & Contemporary Art) — 예:
  `Lot 1 | Corinth, Lovis (1858-1925) | "Sitting woman, c. 1886. Pencil on wove paper…" |
  년도 1886 | 45,5 x 25,5 cm | 추정 800-1200€ | 낙찰 1,036€`
  치수·연도·설명·추정가·낙찰가 전부 정확히 분리 적재됨을 확인
- 기존 DB에 Wikidata 경로(`crawlers/auctions.py --broad`)로 생성된 "Nagel Auktionen"
  auction_houses 행(country="Germany", 기존 auctions 4건)이 이미 있었음 — 이름 기준
  `get_or_create_auction_house`가 그 행을 그대로 재사용해 중복 생성 없이 합류함(정상 동작)

## 6. 후속 과제 (이번엔 하지 않은 것)

1. **카탈로그 없는 회차(2020~2022, 코드 785~810) 처리 불가** — PDF 결과지에 작가명이
   없어 이 프로젝트 스키마로는 로드 불가능. 스킵이 맞는 판단이라고 본다(무명 처리로 억지로
   넣으면 안 됨).
2. **36개 코드 전체 로트 상세 백필** — 회차당 300~480로트, crawl-delay 1.75초 기준
   전체 약 1만~1만5천 요청 ≈ 5~7시간. 이번 세션에서는 파일럿(6회차×10로트)만 검증했고
   전체 백필은 `crawlers/nagel.py --phase lots`(파라미터 없이, 즉 전체)를 별도 백그라운드
   잡으로 돌리는 후속 과제로 남긴다. `already_fetched` 기반이라 중단·재개 안전.
3. **주간 갱신잡(`refresh_weekly.ps1`) 편입** — Grisebach·칸옥션과 마찬가지로 이번엔
   손대지 않음(스케줄러 이미 등록돼 도는 잡이라 범위 밖).
