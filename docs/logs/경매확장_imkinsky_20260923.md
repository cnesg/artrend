# 경매 소스 확장 — Auktionshaus im Kinsky (빈, 오스트리아) / 2026-09-23

직전에 Dorotheum(빈)이 **ToS에서 AI 학습·TDM·임베딩을 명시적으로 금지**해 완전 제외되면서
생긴 오스트리아 공백을 메우는 대체 소스. 예비조사(다른 세션)에서 "가능" 판정을 받았고,
이 문서는 **착수 세션이 직접 재확인한 결과 + 실제 크롤러/로더 구현 + 파일럿 적재 기록**이다.

- 크롤러: `crawlers/im_kinsky.py`
- 로더: `pipeline/im_kinsky.py`
- 1회성 적재 스크립트: `pipeline/_scratch/load_im_kinsky_20260923.py`

## 1. 판정 재확인 (직접 확인, 2026-09-23)

예비조사 내용을 그대로 믿지 않고 전부 다시 확인했다. **결론은 같으나 사실관계 두 가지가
틀려 있어 바로잡았다.**

### 1-1. 도메인 정정 — `kinsky.at` (X) → `imkinsky.com` (O)

예비조사는 `kinsky.at`으로 기록돼 있었다. 실제로 확인하니:

- `kinsky.at` / `www.kinsky.at` → DNS는 해석되지만(81.19.145.30) **443 연결 자체가 거부**
  (`WinError 10061 ConnectionRefused`). 경매사 사이트가 아니다.
- 실제 사이트는 **`imkinsky.com`** (116.202.252.89). `/robots.txt` 200 응답.

### 1-2. robots.txt (직접 fetch)

표준 Drupal 9 기본값(`/core/`, `/profiles/`, `/admin/`, `/user/login` 등 시스템 경로)에
**커스텀 항목이 딱 두 줄**:

```
# Custom Paths
Disallow: /ergebnisse/139/723/2/94833
Disallow: /en/auction-results/139/723/2/94833
```

- 경매결과 경로(`/en/auction-results/**`)는 **이 로트 1건을 뺀 전부 허용**.
- **예비조사의 "그 로트는 이미 404라 실질 영향 없음"은 틀렸다** — 직접 GET하니 **HTTP 200,
  28,499바이트로 멀쩡히 살아 있다.** 즉 진짜로 "이 로트는 크롤링하지 말라"는 의사표시다.
  크롤러에 `ROBOTS_DISALLOWED_PATHS` 상수로 박아 **명시 제외**했다(독문 경로 포함).
- `Crawl-delay` 지정 없음 → 예의상 자체적으로 1.2초 간격.
- AI 봇(ClaudeBot/GPTBot/CCBot/Bytespider 등) 개별 차단 없음. `Content-Signal` 없음.
- 응답 헤더에 `X-Robots-Tag` 없음, 페이지에 `<meta name="robots">` 없음(둘 다 직접 확인).

### 1-3. 법적 문서 전수 검색 — 금지 조항 0건

사이트가 노출하는 법적 문서는 **넷뿐**이고 별도 이용약관/AGB 페이지는 **존재하지 않는다**
(`/agb`, `/nutzungsbedingungen`, `/de/impressum` 전부 404):

| 문서 | URL | 결과 |
|---|---|---|
| Imprint | `/en/impressum`, `/impressum` | 회사 등기·감독관청·Google Analytics 고지뿐 |
| Privacy notice | `/en/privacy-notice`, `/datenschutz` | GDPR 고지뿐 |
| Fees and Conditions | `/en/fees-and-conditions` | 수수료율 표뿐 |
| Withdrawal right | `/en/withdrawal-right` | 소비자 철회권뿐 |

여섯 페이지 전문에 다음 키워드를 정규식 전수 검색 → **히트 0건**:

> text-and-data-mining / TDM / Nutzungsvorbehalt / §42h(오스트리아 저작권법 TDM 유보) /
> sui generis / Datenbankwerk / Datenbankhersteller / künstliche Intelligenz / artificial
> intelligence / machine learning / Trainingsdaten / training data / embedding /
> scrape·scraping / crawl / robot / automated·automatisiert / Vervielfältigung /
> copyright · Urheberrecht / reproduc*

Dorotheum과 정반대다. **TDM 유보도, DB제작자권 주장도, 복제 금지 조항도 없다.**

### 1-4. 기술 조건

- WAF/봇차단 없음. **완전 SSR(Drupal 9)** — JS 렌더링 불필요, 평문 HTML.
- 로트 상세 한 페이지에 작가명 + 생몰 표기, 제목/제작연도/재질/규격/서명,
  **Provenance / Exhibition / Literature 원문**, 추정가,
  **Realized price(수수료·VAT 포함)와 Hammer Price(순수 낙찰가)가 분리 표기**.
- DB `auction_houses`에 kinsky/wiener 관련 행 **0건** — 완전 신규 소스.
- 참고: `www.wienerkunstauktionen.com`은 예비조사대로 도메인 소멸 — 무시.

### 1-5. 최신성

아카이브가 **1996년부터 2026년 6월 경매까지** 이어진다. 최신 회차는
**auction_id 155 "Big Summer Auction 2026"(2026-06-16 ~ 06-18, 6개 부문 세션, 820 로트)**.
예비조사가 "auction_id 150 = 2025년 6월"이라 한 것보다 더 최신까지 있다.
→ 살아있는 소스이며, **마지막 auction_id + 1부터 증분**(`--since-auction`)하는 패턴이라
`refresh_weekly.ps1`(로드맵 7)에 그대로 붙일 수 있다.

**판정: 수집 가능. 착수.**

## 2. 구조와 수집 방식

```
/en/archive                                 -> 경매(회차) id 목록 (169개, id 1~155 + 1111 등)
/en/auction-results/<a>                     -> 그 회차의 부문별 세일 목록 <a>/<s>/<n>
/en/auction-results/<a>/<s>/<n>[?page=N]    -> 로트 목록(40건/페이지)
/en/auction-results/<a>/<s>/<n>/<lot_id>    -> 로트 상세 (원본 저장 대상)
```

1~3단계 결과는 `crawlers/raw/im_kinsky/_index.json`에 캐시(`--refresh-index`로 갱신).
4단계 로트 상세만 `already_fetched()` 기준 증분 수집. 이미지는 저장하지 않는다.

오래된 회차(1996~2000년대 초)는 목록 페이지가 "No lots found."로 **PDF 카탈로그만 있고
로트 데이터가 없다** — 인덱스 단계에서 자연스럽게 0건으로 걸러진다.

## 3. 데이터 관례 (다른 경매 소스와의 차이)

- **`auction_lots.hammer_price`에는 "Hammer Price"(수수료 제외 순수 낙찰가)를 넣는다.**
  im Kinsky는 수수료·VAT 포함가("Realized price")를 따로 표기하는 드문 소스다.
  Lempertz(`offers.price` = 프리미엄 포함), Durán(포함 여부 불명)과 **가격 정의가 다르니
  소스 간 비교 시 주의.** 포함가는 버리지 않고 `artworks.description`에
  `[Realized price (incl. fees/VAT)]` 라벨로 보존.
- 추정가는 `Estimate: € low - high` 구간이 기본. 일부 로트는 `Starting bid: € x` 단일값만
  있어 그때는 `estimate_low`에만 넣고 `estimate_high=None`(kogirekai/Durán 관례),
  description에 `[Note] estimate_low is a starting bid` 주석.
- **작가는 사이트 작가 페이지로 링크된 `<a href="/en/artists/N">`만 인정한다.**
  골동품(Antiques) 로트는 같은 자리에 링크 없는 `<h3>`로 **사물 이름**("Gothic cassette",
  "LOUIS XIII mirror")이 들어온다 — 이걸 작가로 받으면 2026-09-15 재진단에서 걷어낸
  사물명/익명 가비지가 artists에 다시 쌓인다. 링크가 없으면 그 `<h3>`를 **제목**으로 쓰고
  `artist_id=None`.
- 링크는 있지만 실제 인물이 아닌 **"Artist of the 17th century"류 익명 표기**(예: 사이트
  artist id 109152)도 artists 행을 만들지 않고 `[Attribution]` 라벨로 원문만 보존한다.
  단 "Master of ..."류 notname은 미술사 정식 명칭이라 제외하지 않는다.
- **귀속 한정어**: `<h3>Studio of <a>Michael Pacher</a></h3>`처럼 링크 앞에 "Studio of",
  "Attributed to" 등이 붙는다 — 작가명에 섞지 않고 분리해 소문자로 `[Attribution]` 라벨에
  보존(`artworks.attribution_qualifier` 컬럼이 있으나 `store.insert_artwork`의 배치 컬럼
  목록에 없고 `store.py`는 다른 세션이 수정 중이라 이번엔 건드리지 않았다 — 후속 승격 과제).
- **생몰년은 작가 링크가 정확히 1명일 때만** 괄호 표기에서 읽는다(공동작 로트는 괄호 안에
  두 작가 연도가 섞여 잘못 매칭됨). 국적은 넣지 않는다(경매사 소재지로 국적 추정 금지 —
  nagel/kanauction/Durán과 동일 원칙).
- **Provenance/Exhibition/Literature로 provenance_records·collectors·exhibitions를 만들지
  않는다.** 원문이 "private property, Austria"류 익명 일반명사가 절반이라 그대로 구조화하면
  재진단에서 걷어낸 가비지가 재생산된다(Durán 로더와 동일 원칙). `artworks.description`에
  `[Provenance]` 라벨로 **원문만 보존**하고 구조화는 후처리에 맡긴다.
- 제목은 독일식 인용부호(`„…“`)로 감싸여 와서 바깥 한 겹만 벗긴다.
- 낙찰가 없는 로트(유찰/미공개)는 스킵 — 기존 경매 로더들과 동일.
- `sale_key`는 세일 경로(`"139/723/2"`) — 같은 회차 안에서도 부문별 세션마다 별개 auctions
  행. `auctions.name`에 "`<회차명> — <세션명>`"을 직접 채운다(store 인터페이스가 name을
  채우지 않아 로더에서 UPDATE).

## 4. 파일럿 결과 (2026-09-23)

최신 회차 **155 "Big Summer Auction 2026"** 의 로트 상세 **250건**을 수집해 적재했다.

```
크롤링 : 250건 저장, 404 0건, 실패 0건, robots 제외 0건
적재   : 201건 (낙찰가 없는 유찰 로트 49건 스킵, 파싱 실패 0건)
```

| auctions 행 | 날짜 | 로트 | 낙찰가 min/max/평균 |
|---|---|---|---|
| Big Summer Auction 2026 — Antiques | 2026-06-18 | 110 | €300 / €19,000 / €2,781 |
| Big Summer Auction 2026 — Modern Art | 2026-06-17 | 91 | €500 / €400,000 / €15,329 |

필드 충족률(201건 기준): 작가 99, 제작연도 161, 재질 201, 규격 200,
**Provenance 원문 98**, Realized price(수수료 포함가) 201, sources 201.

- 작가가 99/201인 건 **정상**이다 — Antiques 로트 110건은 작가가 없는 사물(가구·공예)이라
  설계대로 `artist_id=NULL`로 들어갔다. Modern Art 91건은 사실상 전량 작가가 붙는다.
- 기존 artists 행 재사용 확인(Gustav Klimt / Carl Moll / Werner Berg 등은 기존 행에 연결,
  신규 생성은 10명뿐) — `get_or_create_artist_safe`로 즉시 upsert해 동시 세션 레이스 회피.
- 샘플 검수 예: 로트 3301 Gustav Klimt, "Seated Naked Pregnant Woman from the Left
  (Study for „Die Hoffnung II", 1907/08)", 1904/05, pencil on paper, 55.2 x 35 cm,
  추정가 €20,000–40,000, **Hammer €40,000** (Realized €52,000은 description에 보존).

## 5. 전량 백필 (착수)

- 실측: 로트 상세 1건당 **서버 응답 약 2.3초**. 단일 프로세스로는 수만 건이 수십 시간.
- **인덱스 빌드 완료(약 75분): 경매 169개 / 세일 356개 / 로트 40,012건.**
  1996~2000년대 초 회차는 목록이 "No lots found."(PDF 카탈로그만)라 0건으로 걸러졌고,
  실질 데이터는 2000년대 중반 이후 회차에 몰려 있다(회차당 600~1,200 로트).
- 인덱스 완성 직후 **4샤드 병렬 백필 자동 기동 확인**
  (`pipeline/_scratch/launch_im_kinsky_backfill_20260923.py`, detached).
  `--newest-first --shard i/4 --delay 1.5` → 샤드별 담당 10,039 / 9,980 / 9,961 / 10,032건
  (로트 id 기준 샤딩이라 균등, 중복 요청 없음). 사이트에 가는 전체 요청률은 초당 1건 안팎
  유지, 처리량 약 4배. **최신 회차부터 역순**이라 중간에 끊겨도 최신성부터 확보된다.
- 예상 소요: 남은 약 39,760건 / 초당 약 1.05건 = **약 10.5시간**.
- 로그: `docs/logs/imkinsky_index_20260923_stdout.log`,
  `docs/logs/imkinsky_backfill_20260923_shard{0..3}_stdout.log`.
- 수집 중/후 적재는 `python pipeline/_scratch/load_im_kinsky_20260923.py --apply`를 반복
  실행하면 된다(`sources.raw_path` 기준으로 이미 적재된 건 건너뛰므로 idempotent).

## 6. 남은 과제

- `artworks.attribution_qualifier` 컬럼으로 `[Attribution] studio of` 류를 승격
  (`store.insert_artwork` 배치 컬럼 목록에 없어 이번엔 description에만 보존).
- `[Provenance]` 원문에서 실명 컬렉션/딜러만 골라 `provenance_records`로 구조화
  (익명 일반명사 제외). 특히 `"Dorotheum, Vienna, 20th March 1995, lot 33"`처럼
  **경매사+날짜+로트번호가 다 있는 줄**은 기존 auction_lots와 매칭할 수 있는 형태다
  (단 `house+lot+year` 세 개를 다 봐야 함 — lot 번호 재사용 이력).
- 주간 자동갱신(`refresh_weekly.ps1`)에 `--since-auction <마지막 회차>` 증분 추가.
