## 2026-09-23 추가분 (공유 문서 미반영 — 통합 시 반영 필요)

09-22 시점 공유 문서에는 K-ARTMARKET 52,651건 / Grisebach 26,800건으로 적혀 있다.
그 뒤 아래 3건을 처리해 수치가 바뀌었다.

### 1. K-ARTMARKET: UCI 없는 로트 2,910건 누락 발견·복구
`parse_items`가 `data-ucicd`(국가표준식별자)를 **필수**로 보고 없는 블록을 건너뛰고 있었다.
출처에는 **UCI 없는 로트가 2,912건(전체 55,729건의 5.2%)** 있고 전부 경매사·낙찰가·경매일이
멀쩡한 실제 로트였다. **페이지 수만 세면 안 보이는 누락**이라
`<div class="list-box">` 블록 수(55,729)와 파싱 건수(52,817)를 대조해서 잡았다.
- 로더 수정: UCI는 있으면 실행 내 중복 제거 키로 쓰고, 없으면 페이지 내 순번으로 대체
- 이미 적재된 페이지는 `source_already_loaded`로 스킵되므로 백필 신설:
  `pipeline/k_artmarket_backfill_missing_lots.py` (리포트/`--apply`, idempotent —
  페이지마다 (제목·재질·규격·낙찰가) 키로 기존 개수를 세고 **남는 만큼만** 넣는다)
- 결과: **+2,910건** 적재 → 52,651 → **55,561건**. 재실행 0건으로 idempotent 확인
- 미적재로 남는 168건 = 경매사 칸 복구 불가 155 + 출처 가격 오버플로 13

### 2. K-ARTMARKET: '-' 작가 행 정정 (내가 만든 결함)
출처가 작자 미상 행의 **작가명 칸에 하이픈만** 넣어 두는데, 1차 적재가 이를 실제 이름으로
취급해 `artists`에 **`'-'`라는 작가 행을 만들고 작품 5,017건을 거기에 묶었다.**
- 로더 수정: `_person_name()` — 영숫자/한글이 하나도 없는 값은 이름 없음으로 처리
- 이미 들어간 데이터는 되돌림: 해당 5,017건 `artworks.artist_id`를 NULL로, `'-'` 행 삭제
  (다른 테이블 참조 0건 전수 확인 후. 명백한 가비지 + 화이트리스트 1행 + idempotent)
- **이 정정 때문에 작가 연결률이 77.9% → 66.8%로 내려갔다.** 숫자는 내려갔지만 이게 맞는
  값이다 — 5,017건은 실제로 작자 미상이다

## 공용 코드 변경 (다른 로더에 영향 있음 — 통합 시 확인 필요)

- `pipeline/store.py` — `get_or_create_auction(..., sale_key=)` 추가. 기존엔 (경매사, 날짜)로만
  캐싱해 **같은 날 여러 세일이 한 auctions 행으로 뭉개지고 날짜 모르는 소스는 전부 한 행**이
  되는 한계가 있었다(bonhams.py 주석에 기록돼 있던 그 문제). 기본 동작은 그대로
- `pipeline/raw_iter.py` — `iter_records(..., ext=)`(HTML 원본 지원),
  `ARTREND_RAW_ROOT` 환경변수(워크트리에서 메인 체크아웃의 공용 raw 캐시 참조)
- `pipeline/auctions.py` — `NON_AUCTION_EVENT_LABELS` 필터 추가(`--broad`가 끌어온
  구입/수여/평가 등 경매 아닌 사건 제외), `DOMAIN_TO_HOUSE`에 단일 경매사 도메인 2개 추가
- `pipeline/merge_auction_house_variants.py` — 국내 경매사 alias 추가
  (`라이즈`→라이즈아트, `마이`/`마이아`→마이아트옥션). **정확 접두 일치 건만** 넣었고,

  교차언어/오타 추정이라 `EXCLUDED_AMBIGUOUS`에 사람 판단용으로 남김
- **DB 인덱스 11개 신설** — `sources`를 참조하는 FK 컬럼(`artists`/`auction_lots`/
  `provenance_records`/`museum_holdings` 등)에 인덱스가 없어 sources 삭제가 수 분씩 걸렸다.
  `idx_<table>_source_id` 생성 후 전부 수 초. 영구 개선

## 알려진 한계 / 후속 과제

1. **Grisebach 약 2% 누락** — 특정 오프셋 페이지가 `sortBy`와 함께 부르면 항구적 HTTP 500
   (60·147·151 등 7페이지). 기본 정렬로는 200이고 desc 대응 오프셋도 동일하게 500이라
   사이트 쪽 정렬 쿼리 버그. 회수하려면 기본 정렬로 한 번 더 돌아 object id로 합치면 된다
   (로더가 이미 object id로 중복 제거)
2. **Grisebach 가격은 구매수수료 포함가**("Sold for … (incl. premium)") — Bonhams(해머
   프라이스)와 정의가 다르다. 소스 간 가격 비교 시 주의
3. **칸옥션 경매일은 연 단위** — 사이트가 회차명만 공개하고 날짜를 안 준다. 지어내지 않고
   연도별 검색 필터로 "그 해 첫/마지막 회차"만 받아 회차→연도를 **정확히** 판정한 뒤
   `YYYY-01-01`로 적재(`raw_iter.year_to_date` 관례). 2022년 이후 국내 로트는
   K-ARTMARKET 쪽에 정확한 날짜와 함께 들어 있다
4. **K-ARTMARKET 증분은 새 뒷페이지로만 들어온다** — `auction_lots`에 UCI를 담을 컬럼이
   없어 페이지 재수집(`--refetch-last`)분은 `sources.raw_path` 스킵에 걸린다.
   UCI 컬럼 추가(마이그레이션)가 깔끔한 해법
5. **주간 갱신잡(`refresh_weekly.ps1`)에 신규 3소스 미편입** — 이미 스케줄러에 등록돼
   돌고 있는 잡이라 이번 범위에서 건드리지 않았다. 셋 다 `already_fetched` 기반이라 증분은
   값싸다: `grisebach.py --phase all`, `kanauction.py --phase all`, `k_artmarket_works.py`
