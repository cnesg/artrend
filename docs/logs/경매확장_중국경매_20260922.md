## A. China Guardian(中国嘉德, cguardian.com) — 불가 확정

robots.txt(`https://www.cguardian.com/robots.txt`, 2026-09-22 직접 확인)를 전문 읽었다.
화이트리스트형 구조다 — googlebot/googlebot-news에게만 개별 규칙을 주고, **그 외 모든
크롤러("User-agent: *")는 파비콘 하나만 허용하고 나머지 전부 `Disallow: /`**:

```
# 其他爬虫全部禁止
User-agent: *
Allow: /favicon.ico
Disallow: /
```

게다가 googlebot 규칙조차 경매 관련 경로를 별도로 명시 차단한다:

```
# 禁止拍卖相关路径（大小写都覆盖）
Disallow: /auction*
Disallow: /Auction*
```

즉 (1) 일반 크롤러는 애초에 전면 차단이고, (2) 설사 예외를 인정받는 봇이라도 낙찰결과가
있는 `/auction*` 경로는 별도로 막혀 있다. 이 프로젝트의 "robots.txt 통과 + ToS 통과 둘 다
확인" 원칙에서 robots.txt 단계부터 탈락 — ToS(用户协议) 확인 단계로 넘어갈 필요도 없이
**불가로 확정**하고 재검토 대상에서 제외한다.

(참고: 홈페이지 자체는 정상 응답하고 CDN/WAF로 인한 접속 불가는 아니었다 — 명시적 정책
거부이지 "가용성 문제"가 아니다.)

## B. Poly Auction(北京保利, polypm.com.cn) — 가능, 착수 완료

### B-1. robots.txt — 제한 없음

`www.polypm.com.cn`·`en.polypm.com.cn`·`csen.polypm.com.cn` 세 서브도메인 모두
`/robots.txt` 요청이 **HTTP 404**(파일 자체가 없음, nginx 기본 404 페이지 — WAF 차단이나
빈 파일이 아니라 진짜 없음). robots.txt 부재는 관례상 제한 없음으로 해석한다.

### B-2. 이용약관 — 별도 ToS 페이지 없음, `/laws/`가 사실상 유일한 법적 페이지

사이트 전체 nav를 훑어도 "이용약관/개인정보처리방침" 같은 웹사이트 자체 ToS 페이지가
없다. 유일한 법적 문서 페이지는 `/laws/`(Laws)이고, 그 안에 3개 탭이 있다:

1. **拍卖规则(Auction Rules)** — 제66조, 경매 참가자(위탁자/경매인/매수인)의 권리의무를
   규정하는 회사 자체 규칙. 크롤링/스크래핑/데이터마이닝/제3자 정보제공 금지 조항
   **없음**(전문 확인). 저작권 관련 조항은 **제59조** 하나뿐:
   > "本公司有权自行对委托人委托本公司拍卖的任何物品制作照片、图示、图录或其它形式的
   > 影像制品,并依法享有上述照片、图示、图录或其它形式的影像制品的著作权"
   → 회사가 직접 촬영한 사진/도록의 저작권 조항 — 칸옥션 제7조③과 동일한 성격.
   **작품 사진은 수집하지 않고 텍스트 사실 데이터만 저장**하는 것으로 지킨다.
2. **拍卖法(중화인민공화국 경매법)** — 국가 법령 전문(1997년 시행), 경매업 일반 규제.
   크롤링과 무관.
3. **文物保护法(문화재보호법)** — 국가 법령 전문, 문화재 보호·거래 규제. 크롤링과 무관.

세 문서 어디에도 "禁止抓取/爬虫/数据挖掘/向第三方披露"(크롤링/스크래핑/데이터마이닝/
제3자 개시 금지) 같은 문구가 없다. 일본 경매사들(SBI Art Auction, Est-Ouest)에서 봤던
"제3자 정보개시 금지" 패턴도 없음을 확인했다 — 애초에 이 페이지는 경매 입찰 참가자 간의
권리의무 규칙이지, 웹사이트 이용에 관한 약관이 아니다(위탁자·경매인·매수인만 당사자로
정의, "이용자"/"방문자" 개념 자체가 없음).

**결론**: 명시적 크롤링 금지가 없고 robots.txt도 없어 조건부 진행 — K-ARTMARKET(공적
공개 데이터, 별도 ToS 없이 robots만 확인하고 진행한 전례)과 같은 근거 강도다.

### B-3. 구조 — SPA 프론트엔드지만 내부 JSON API가 인증 없이 열려 있음

홈페이지의 "拍卖结果(Auction Results)" 섹션과 하위 `/auction` 페이지는 눈에 보이는 HTML
자체는 SPA라 비어 있다(`Loading...` 대신 빈 `<div>`, jQuery AJAX로 채움 — mmca.py가
다뤘던 것과 같은 패턴). 하지만 그 AJAX가 부르는 내부 API 3단이 **인증·키 없이 그대로
GET으로 열려 있다**:

```
/notice/list?startTime=&noticeName=&pageSize=N&isShow=T&pageNum=N   # 拍卖会(경매 이벤트) 목록
/session/getSessionList?noticeId=<경매이벤트id>&oldData=true|false   # 专场(세션) 목록
/item/list?sessionId=<세션id>&oldData=true|false&pageSize=N          # 로트 목록 — 낙찰가 포함
```

- `/notice/list`: 2005-11-06(2005秋季拍卖会)부터 2026-09-22 현재까지 **총 334개** 경매
  이벤트를 `pageSize=2000` 한 번 요청으로 전부 받았다(페이지 밀림 걱정 없음 — Grisebach의
  가격순 정렬 문제와 달리 단일 요청으로 전체를 받으므로 페이지 경계 자체가 없다).
- `/item/list` 응답 필드: `itemNamePpch`(제목, 서화는 작가명이 앞에 붙는 패턴), `lotNo`,
  `dealStatus`(1=유찰 2=성사 3=취소 4=매수인위약 5/6=철회), `dealPrice`(낙찰가),
  `valLow`/`valHigh`(추정가), `porcelainPropertie1~4`(크기/제작연도/재질/표구형식),
  `itemRemark`(설명, HTML). 표본 확인(2005년 근현대서화 세션, 743건 중 낙찰 497건)에서
  `dealPrice`가 정상적으로 채워져 있음을 직접 확인했다.
- 구조화된 작가 필드(`authorCh`)는 **표본상 항상 null** — 서화 카테고리는 제목이
  "작가명 + 표구형식(镜心/立轴/手卷 등)"으로 끝나는 패턴이 강해 그 경우에만 선행
  순한자 2~5자를 작가명으로 파싱하고, 그 외 카테고리(도자기·옥기·화폐 등, "清乾隆 …"
  처럼 다른 패턴)는 오탐 위험이 커서 **파싱하지 않고 제목 전체만 저장**한다
  (칸옥션의 "생몰년 안 붙으면 작가로 인정 안 함"과 같은 보수적 원칙).
- 가격 단위는 CNY(人民币) — 拍卖规则 제49조가 "所有价款应以本公司指定的货币支付"라고만
  하고 별도 표시가 없는 건 전부 위안화로 간주.
- 이미지(`coverUrl`)는 수집하지 않는다(B-2의 제59조 저작권 조항).

  낮고 위험하다고 판단해, **크롤링과 별도로 5분 간격 증분 적재 루프(task bjmx5egof)를
  병행 실행**하기 시작함 — `already_fetched`/`source_already_loaded` 덕분에 언제 돌려도
  idempotent, 실패해도 다음 5분 회차에 조용히 재시도(사실상 무제한 인내). 첫 회차(10:07)는
  실제로 `psycopg2.OperationalError: server closed the connection unexpectedly`로 실패
  — 그 시점에 pgportable이 다시 죽어 있던 것도 직접 확인(`connection refused`). 사용자
  보고("오늘 이미 두 번 죽었다")가 실시간으로 재현된 것.
