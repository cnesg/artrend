# Koller Auktionen(취리히) 조사 — 불가 확정 (2026-09-22)

## 결론
**불가 — 착수하지 않음.** 로트 데이터 구조·ToS 확인 단계까지 가지도 못했다.
`kollerauktionen.ch`(www 포함 모든 페이지 확인한 범위 내)가 **robots.txt 요청 자체를
포함해 전 페이지에서 JS 연산 기반 봇 챌린지("Please wait while we validate your
browser")를 강제**한다. 이 챌린지를 통과하려면 브라우저에서 JavaScript로 소인수분해
연산을 수행하고 그 결과로 쿠키(`FUSION_SECPROFILE_SECKEY=...`)를 계산해 재요청해야
한다 — 명백한 능동적 봇 차단(proof-of-work WAF challenge)이다.

## 확인한 것
- 도메인: 공식 사이트는 `kollerauktionen.ch`(독일어권 표준), 영문 별칭
  `kollerauctions.com`은 `kollerauktionen.ch`로 301 리다이렉트됨.
- `https://www.kollerauktionen.ch/robots.txt` — HTTP 200이지만 본문이 robots.txt가
  아니라 위 JS 챌린지 페이지. `curl` 응답 헤더에 `content-type: text/html`,
  `cache-control: no-cache`만 있고 표준 WAF 벤더 헤더(cf-ray 등)는 없어 Cloudflare가
  아닌 별도 WAF/CDN(챌린지 쿠키 이름 `FUSION_SECPROFILE_*`로 미루어 Barracuda/Fusion
  계열 추정, 벤더 확정은 안 함)로 보인다.
- `https://www.kollerauktionen.ch/en/online-auctions/`(경매 목록 페이지, 향후 결과
  아카이브로 이어질 경로)도 **동일한 JS 챌린지**로 응답 — robots.txt만이 아니라
  콘텐츠 페이지 전반이 막혀 있다.
- 이 상태로는 robots.txt 원문도, 이용약관 원문도, 결과 페이지 구조(SSR 여부)도 **확인
  자체가 불가능**하다. 챌린지를 우회(JS 실행·쿠키 위조 등)하는 것은 봇 탐지 우회이므로
  이 프로젝트 원칙(`docs/경매소스확장_20260922.md` B-4절, "우회는 봇 탐지 우회라 하지
  않는다")과 상위 안전 규칙 모두에 어긋나 시도하지 않았다.

## 판정 근거
같은 문서 B-4절에 이미 확정된 사례들과 동일 패턴:
- Chiswick Auctions — robots.txt 요청이 JS proof-of-work 봇 챌린지로 응답
- Roseberys — robots.txt·과거경매 페이지 모두 봇 보호 계층에 막힘
- easyliveauction.com — robots.txt조차 챌린지에 막힘

Koller도 이 셋과 같은 범주("robots.txt 자체가 능동적 봇 차단에 막혀 확인 불가")로
**불가 확정**한다. Grisebach(ClaudeBot 명시 허용)와는 정반대 극단의 사례.

## 이번 세션에서 한 일
- robots.txt 확인 시도(2개 도메인) → 챌린지 확인, 중단.
- 결과 목록 페이지 접근 시도 → 동일 챌린지 확인, 중단.
- ToS 원문 확인, 크롤러/로더 작성, DB 적재는 **전부 진행하지 않음**(선행 조건 미충족).
- `crawlers/koller.py`, `pipeline/koller.py` — **작성하지 않음**.

## pipeline/run.py에 추가할 내용
없음 — 적재하지 않았으므로 추가할 항목 없음.

## 후속 참고
다른 네트워크/환경에서 챌린지가 재현되지 않을 가능성은 있으나, 이 프로젝트 원칙상
봇 차단을 우회해서 접근성을 재시도하는 것 자체가 목적에 어긋난다. 스위스 경매사
대안이 필요하면 Koller 외 다른 스위스 경매사(예: Beurret Bailly Widmer, Dobiaschofsky
등)를 신규로 탐색하는 편이 낫다 — 이번 세션 범위 밖.
