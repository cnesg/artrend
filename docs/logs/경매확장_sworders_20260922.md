# Sworders 착수 로그 (2026-09-22)

## 최종 판정: **가능 — 착수 완료**

## 0. 가장 중요한 발견: 오케스트레이터 지시서의 도메인이 틀렸다

`docs/경매소스확장_20260922.md` B-5절의 "Sworders(sworders.co.uk)"는 **잘못된 도메인**이다.

- `sworders.co.uk`(복수형 s)로 접속하면 Sworders와 무관한 제3자 호스팅사(3itltd.co.uk)의
  "under construction" 플레이스홀더 페이지가 나온다. curl로 직접 확인 시 TLS 인증서
  SNI mismatch(`SEC_E_WRONG_PRINCIPAL`)까지 발생했고, `-k`로 인증서 검증을 무시하고 받아도
  콘텐츠는 플레이스홀더뿐이었다. Anthropic 인프라를 통한 WebFetch로도 동일하게 확인해
  로컬 네트워크/DLP 문제가 아님을 배제했다(Ketterer Kunst 사례처럼 로컬 schannel 문제였을
  가능성을 먼저 의심했으나, 이번엔 진짜로 사이트 자체가 다른 곳이었다).
- WebSearch로 재확인한 **실제 공식 도메인은 `sworder.co.uk`(단수형)**. 원 조사(B-5절)가
  아마 오탈자 하나로 완전히 다른(무관한) 사이트를 판단 대상으로 삼았던 것으로 보인다.
- 이 착수는 실제 도메인(`sworder.co.uk`)을 기준으로 진행했다. `SITE_NAME`/raw 캐시
  디렉터리명은 기존 조사 문서와의 연속성을 위해 "sworders"로 유지.

결과·경매·로트 경로(`/results/`, `/auction/details/`, `/auction/lot/`)에는 제한이 없다.
`crawl-delay: 10`을 명시(봇을 상정한 조건부 허용 신호) — 크롤러가 그대로 지킨다.

## 2. 이용약관

일반 "웹사이트 이용약관"은 없고, 경매 유형별 매매조건(Terms & Conditions) 3종만 있다:
Specialist Live Auctions / Homes and Interiors Auctions / Online Timed Auctions. **3종 전문을
직접 읽어 확인한 결과 crawling/scraping/spidering/robot/bot/data mining/harvesting/
systematic downloading 키워드가 전혀 없다.** 저작권 조항은 사진·카탈로그 텍스트에 대한
Sworders 소유권뿐이라 — **사진은 수집하지 않고 텍스트 사실 데이터만 저장**한다(칸옥션과
동일한 대응 방식).

## 3. 구조 — 완전 SSR (curl로 직접 확인, JS 불필요)

- `/results/?y=YYYY` — 연도별 세일 목록. 세일당 슬러그/`au` id/세일번호/날짜가 텍스트로 있다.
  Year 셀렉트가 2018~2026 제공(2017은 0건 실측 확인).
- `/auction/details/<slug>/?au=<id>&pn=<page>&pp=96` — 세일별 로트 목록(페이지당 최대
  96건). "Lot N", 작가명(국적, 생몰년), 작품명, "Sold for £X" 또는 "Estimated at £X - £Y"가
  전부 원본 HTML 텍스트. 예: A1322(Fine Interiors, 415로트) 5페이지, pn=6은 로트 0건.

## 4. 크롤러 버그 하나 발견·수정 (기록해 둘 가치가 있음)

최초 구현에서 "마지막 페이지 판정"을 `"Lot " in html` 순진 문자열 검사로 했는데, **모든
페이지의 내비게이션에 "Lot Alerts"/"Lot Archive"/"Lot number"(정렬 옵션)가 고정으로 떠 있어서
이 문자열이 절대 사라지지 않는다** — 그 결과 진짜 마지막 페이지(pn=3) 이후에도 무한정
pn=4, 5, 6...으로 계속 요청했고, au=753 세일(North Mymms Park)에서 pn=90까지 가서야
사이트의 429(Too Many Requests)를 맞고서야 드러났다. 실제 로트 카드에만 있는
`class='lot-title` 마커로 판정하도록 고쳤고(`crawlers/sworders.py`의 `LOT_CARD_MARKER`),
버그 때문에 저장된 빈 페이지 48개(`lot_753_p004~p051`)는 전수 확인(전부 로트 0건) 후 삭제,
재수집했다. 방어적으로 세일당 300페이지 안전장치도 추가.

파싱 쪽에서도 오탐 1건을 발견·수정했다: 장식미술 설명문 끝에 우연히 역사적 인물의 생몰년이
괄호로 붙는 경우(예: "A rare C J Spooner fairground/carousel 'Boer War' centaur in the form
of General Redvers Buller (1839-1908)" — 실제로는 C J Spooner가 만든 회전목마 장식이지
Buller가 작가가 아니다)를 작가로 오인했다. 사람 이름은 보통 짧다는 점(60자 미만)과 "A/An/The"로
시작하지 않는다는 점을 이용해 필터링(`pipeline/sworders.py`의 `GENERIC_LEAD_RE` + 길이 제한).
이 버그로 잘못 들어간 DB 레코드 1건(artist 1 + artwork 1 + auction_lot 1)은 이름 정확 일치로
전수 확인 후 삭제했다(`pipeline/_scratch/cleanup_sworders_bad_artist_20260922.py`).

## 5. 스코프 필터(작가 판정) 설계

로트 카드 본문 첫 줄이 "이름 (국적, YYYY-YYYY)" / "이름 (YYYY-YYYY)" / "이름 (b.YYYY)" 패턴에
매치할 때만 작가로 인정한다. 괄호 안에 4자리 연도가 없으면(가구·도자기 등 장식미술, "English
School" 같은 익명 귀속) 작가를 비워 두고 **그 로트는 적재하지 않는다**. "After/Attributed
to/Circle of/Manner of/Follower of/School of/Studio of/In the manner of" 같은 귀속 한정어가
붙은 경우도 원작자가 아니므로 스킵한다. 별도 부서 필터 없이 이 규칙 하나로 Bonhams의 WOA
부서 제외와 같은 효과(장식미술 자연 배제)를 낸다 — 실측으로 순수 작가 판매 세일(Modern
British Art 등)은 76%(73/96), 혼합 세일(Fine Interiors 등)은 5~7%만 작가 매치됐다.

## 6. 파일럿 결과 (2026-09-22)

- 세일 12개(2018년 1~4월, au_id 753~767 오름차순) × 48개 로트 페이지 수집.
- DB 적재 **181건**(중복 0건, `select count(*), count(distinct lot_number||auction_id)`로

- 표본 확인: 최고가 로트 John Glover OWS "THE BEGGAR'S OAK" £94,000(1767-1849), 통화 전부

- 적재 스크립트: `pipeline/_scratch/load_sworders_20260922.py`(run.py를 거치지 않고

## 7. 전체 규모 추정 및 후속

전체 세일 523개(2018~2026, `sales_*.html` 9개 연도 파일에서 파싱). 세일 하나당 평균 3~4
페이지 × 세일당 5~76%가 작가 매치라 최종 로트 수는 세일 구성에 따라 크게 갈린다(장식미술
비중 높은 "Fine Interiors"/"Homes and Interiors"는 낮고, "Modern British Art"/"Old Master"류는
높음). `crawl-delay: 10`을 지키면 523개 세일 전체 수집에 대략 4~6시간 소요 예상.

**이 로그를 쓰는 시점에 나머지 511개 세일에 대한 전체 수집을 백그라운드로 이어서 돌려놓았다**
(`python crawlers/sworders.py --phase lots`, `already_fetched` 기반이라 중단·재개 안전).
완료 후 전체 적재는:
```
DATABASE_URL="postgresql://postgres@127.0.0.1:5433/artrend" python pipeline/_scratch/load_sworders_20260922.py
```
를 한 번 더 돌리면 된다(`source_already_loaded`로 기존 12세일은 자동 스킵, 나머지만 신규
적재됨 — run.py 없이도 재실행 가능).
