## 3. 구조 확인 — SSR, JSON-LD로 구조화 데이터까지 제공

- sitemap 구조: `sitemapindex.xml` → `sitemap-en-lots-N.xml`(영문, 샤드당 최대 5,000건).
  **2026-09-22 실측: 18개 샤드, 총 86,806건** 로트 URL.
- 로트 페이지(`/en/catalogues/lot/<경매번호>-<세션>/<로트번호>-<슬러그>.html`)는 완전 SSR —
  `curl`(JS 실행 없이) 그대로 받아도 낙찰가·추정가·작가·제목·설명이 평문으로 들어 있음.
  샘플: `https://www.lempertz.com/en/catalogues/lot/822-1/377-pablo-picasso.html` 확인.
- **`<script type="application/ld+json">` Product 스키마가 가장 신뢰도 높은 구조화 데이터를
  제공** — `offers.lowPrice`/`highPrice`(추정가), `offers.price`(낙찰가, 구매수수료 포함),
  `offers.priceCurrency`, `offers.creator[].name`("성, 이름" 순서)이 전부 이 JSON 한 블록에
  있어 HTML class 파싱보다 훨씬 안정적이다. 설명 전문은 JSON-LD가 아니라(이건 "&hellip;"로
  잘린 요약임) 별도 `<div class="lot-description"><p>...</p></div>`에 있음 — 둘 다 대응하도록
  파서를 작성함.
- 경매일자는 JSON-LD에 없고, 입찰마감 카운트다운의 `data-end="YYYY-MM-DD HH:MM:SS"`에서 얻음.

### 3-1. sitemap에 죽은 URL이 섞여 있다 (실측으로 발견, 중요)

**직접 GET으로 확인하기 전까지는 몰랐던 함정.** sitemap 첫 샤드(0번, `lastmod` 최신순으로 보임)
최상단 115개 URL(카탈로그 번호 30002/30003/30006, 비공개·특수 세일로 추정)이 전부
`/en/404.html`로 302 리다이렉트된다. **상태코드만으로는 걸러지지 않는다** — TYPO3가 302로
리다이렉트하고 `curl -L`/`requests`(둘 다 GET 기본 동작)가 따라가면 최종 응답은 **200**(404
안내 페이지 자체가 200으로 서빙됨)이라, 최종 URL이 `/en/404.html`로 끝나는지 봐야만 걸러진다.
반면 일반 카탈로그 번호(수백~1200번대) 샘플 10개(각 shard 1~17에서 1개씩)는 전부 200 정상
응답 — 죽은 URL은 이 특수 30000번대 카탈로그에 국한된 것으로 보인다(전체 비율은 shard 0
기준 115/5000 ≈ 2.3%, 전체 균질하진 않을 수 있음 — 앞쪽에 몰려 있었음).

크롤러(`crawlers/lempertz.py`)가 최종 URL을 확인해 죽은 링크를 `_dead_urls.txt`에 기록하고
건너뛰도록 처리함(재실행 시 재요청 안 함).

### 파일럿 중 실제로 잡은 버그 3개 (실측 없이는 몰랐을 것들)

1. **sitemap에 진짜 HTTP 404가 섞여 있다**(세션 번호가 중복된 것 같은 깨진 경로, 예
   `.../1311-1-1/8-joseph-beuys.html`). 처음엔 `_get()`(raise_for_status + 4회 재시도)를
   그대로 썼다가 존재하지 않는 페이지를 매번 최대 35초씩 재시도하며 낭비 — 전용 `_get_lot()`을
   만들어 404는 즉시 죽은 링크로 확정하고, 5xx/429만 재시도하도록 분리함.
2. **로트번호를 breadcrumb(`itemprop="name"`)에서 뽑던 최초 파서가 작가 미상 로트(부족
   미술품 등)에서 전부 실패**(breadcrumb 구조 자체가 다름). 항상 존재하는
   `<h1 class="h5 lot-number ...">Lot NN</h1>`로 교체.
3. **JSON-LD `name`(제목)이 작가 미상 로트에서 원본 데이터 품질 문제로 뭉개진다** —
   원래 "제목 / 산지 / 재질" 세 줄인데 JSON-LD 생성 시 구분자 없이 그대로 이어 붙여
   "Zulu hat ( Isicholo )Msinga District, South AfricaHuman hair..."처럼 나옴. 같은 내용을
   줄바꿈 그대로 가진 `<h2 class="lot-title">`에서 첫 줄만 취하는 것으로 대체(제목만 깔끔하게
   분리됨, 작가 있는 로트는 기존과 동일하게 "작가 - 제목" 그대로 유지).

파일럿 규모(13건)에서는 위 3개를 전부 고치고 재적재까지 확인 완료. 대규모 실행 전 미리
잡아낸 셈이라 향후 8만 건 규모 실행에서 데이터 품질 이슈가 될 뻔한 것을 막았다.

## 6. `pipeline/run.py`에 추가할 한 줄 (전량 재크롤 시)

run.py를 이번 작업에서 열어 정확한 등록 패턴(다른 사이트들이 어떤 형태로 등록돼 있는지)을
확인하지 않았다 — 다른 에이전트가 동시 편집 중이라는 지시에 따라 건드리지 않음. 개념적으로는
Grisebach/Kanauction과 동일한 자리에 한 줄:

```python
"lempertz": lempertz.load,   # crawlers/lempertz.py로 수집한 raw/lempertz/*.html을 적재
```

정확한 문법은 run.py를 직접 열어 기존 site 등록 방식(딕셔너리인지 if/elif 체인인지)에
맞춰 넣어야 함 — 이번 세션에서 확인 못 함.
